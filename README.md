# Рацион — Android-приложение учёта питания

Однопользовательское офлайн-приложение: кладовая, заготовки, шесть приёмов пищи в день, которые собираются из продуктов и отдельных блюд, напоминания, вес и давление. Без регистрации, сервера, аналитики и рекламы. Интерфейс на русском, 24-часовой формат, часовой пояс устройства, метрические единицы.

> «Рацион» не является медицинским приложением: он показывает цели и предупреждения по заданным правилам и не заменяет врача.

В репозитории также лежит несвязанный каталог `featurescript/` (Onshape) — к приложению отношения не имеет.

## Сборка и запуск

Требуется JDK 17+ и Android SDK (платформа 36). Путь к SDK — в `local.properties` (`sdk.dir=...`) или `ANDROID_HOME`.

```bash
./gradlew assembleOfflineDebug     # основная сборка для пользователя (без INTERNET)
./gradlew assembleApiDebug         # сборка с необязательным режимом Claude API
./gradlew assembleDebug            # обе
./gradlew test                     # юнит-тесты
./gradlew lint                     # статический анализ
./gradlew dependencyUpdates        # проверка версий зависимостей
./gradlew assembleOfflineRelease   # release: R8 + shrinkResources, debuggable=false
```

### Сборка на GitHub Actions

Workflow `.github/workflows/android.yml` запускается на каждый push (и вручную: Actions → Android APK → Run workflow). Он собирает debug APK обеих сборок, проверяет, что в offline нет `INTERNET` (`aapt dump permissions`), затем гоняет юнит-тесты и lint. Готовые APK — в артефакте `ration-apk-<sha>` на странице запуска (Summary → Artifacts), отчёты — в `reports-<sha>`. Для телефона нужен файл `app-offline-debug.apk` (разрешить установку из неизвестных источников).

Установка: `adb install app/build/outputs/apk/offline/debug/app-offline-debug.apk`.

### Сборки (product flavors)

| Flavor | INTERNET | Режим Claude API | applicationId |
|---|---|---|---|
| `offline` (по умолчанию, выдаётся пользователю) | нет | недоступен | `com.ration.app` |
| `api` | да, только для раздела 5.6 | включается вручную с ключом | `com.ration.app.api` |

## Структура

Один модуль `app`, пакеты по слоям:

- `domain` — чистая логика без Android: парсер импорта и промпты, списание FIFO, пороги 40/20, планировщик дня, пересчёт после съеденного, предупреждения, правила напоминаний, замены, недельные счётчики, резервная копия (JSON + AES-GCM), отчёт для врача.
- `data` — Room (сущности, DAO), DataStore (настройки одной JSON-строкой), EncryptedSharedPreferences (API-ключ), засев (`data/seed/SeedData.kt`), репозитории, чтение календаря.
- `notifications` — AlarmManager (`setExactAndAllowWhileIdle`, при отказе в точных будильниках — неточный `setAndAllowWhileIdle`), ресиверы, WorkManager-страховка каждые 6 часов.
- `ui` — Jetpack Compose + Material 3, Navigation Compose, Hilt ViewModel.

## Раздел 19 (версия 1.2.0): «Сегодня», шесть приёмов, без типов дня

- **Шесть приёмов** в фиксированном порядке: З — завтрак, С — перекус, О — обед, П — перекус, У — ужин, Е — перекус. До версии 1.2 в базе были слоты `SNACK_1`, `SNACK_2` и `ROAD_BAR` («Перекус 1», «Перекус 2», «Батончик в дороге»). Все три стоят между обедом и ужином, поэтому стали «П». Слота «С» (перекус между завтраком и обедом) раньше не было, он новый.
- **Карточка приёма** — ровно две кнопки:
  - «не отмечен»: «Пропустить» и «Собрать из продуктов»;
  - «пропущен»: «Отменить пропуск» и «Собрать из продуктов»;
  - «записан»: показывает состав и итог, кнопки «Добавить ещё» и «Изменить».
  - Рекомендованных блюд и готовых сетов на вкладке нет. Итоги дня считаются только по записанному.
- **Автопропуск.** Первая запись в слот пропускает все более ранние неотмеченные слоты того же дня (помечаются «пропущен (авто)»).
  - Записанные и вручную пропущенные слоты не меняются, более поздние не затрагиваются.
  - Запись, списание и статусы выполняются одной транзакцией. Отмена записи возвращает автопропущенные слоты в «не отмечен», если их потом не меняли вручную.
  - Пропуск не трогает склад и недельные счётчики. По пропущенным слотам нет напоминаний «нет записи».
- **Быстрое меню** не изменилось и стоит строкой над карточками: вода, эспрессо, батончики, алкоголь, «Свой продукт», «Собрать из продуктов». Запись со слотом подчиняется автопропуску, вода и кофе статусы не меняют.
- **«Собрать из продуктов»** — конструктор раздела 12 в контексте слота.
  - Список содержит продукты библиотеки и отдельные блюда. Блоки З1–Е6 разбиты на компоненты: «лосось 180 г», «батат из заготовки 200 г» и т. п. Списание идёт по сырому весу компонента.
  - Блюда «на улице» и батончики остаются одним блюдом с ккал и белком из таблицы, без списания.
  - Исходные блоки не удалены, только скрыты (`hidden`). Свои блоки M… — в свёрнутой группе «Мои сеты».
  - «Что приготовить» (раздел 18) открывается из меню конструктора ⋮ и из уведомления о нехватке белка. Цель приёма = остаток дневной цели / число неотмеченных слотов впереди.
- **Типов дня нет:**
  - одно расписание шести слотов (Настройки → Время приёмов);
  - одна цель ккал, белка и воды — три прогресс-бара на «Сегодня»;
  - подсказка по календарю и разрешение `READ_CALENDAR` удалены вместе с типами дня;
  - колонка `day_plan.dayType` сохранена и больше не читается, история прошлых дней с типом дня остаётся в базе и в копии.
- **Напоминания:** «нет записи» через 120 минут для завтрака, обеда и ужина. Для перекусов С, П, Е — по переключателю в настройках (по умолчанию выключено), потому что раньше перекусы были только в дни типа А.

### Статистика калорий и белка (1.2.1)

«Ещё → Калории и белок» или «Вес и давление → Питание». Считается только по журналу питания, без календаря и без дополнительных разрешений.
- Период: 7, 14, 30 или 90 дней.
- Средние ккал и белок за день. Дни без записей в средние не входят.
- Доля калорий из белка.
- Число дней в норме ккал, дней с белком не ниже минимума, дней с перебором больше 10%; серия дней с нормой белка.
- Самый лёгкий и самый тяжёлый день.
- Столбцы по дням с линиями нормы.
- Средние по неделям и по приёмам (З…Е).

Вес, давление и отчёт для врача не менялись. Разрешение календаря им никогда не требовалось: оно было нужно только подсказке типа дня, удалённой в 1.2.0.

### Обновление на 1.2.0 (база v2 → v3)

- **Перед миграцией:** файл базы и WAL копируются в приватную папку `files/backup/pre-migration-<версия>.db`, хранятся 2 последние копии. Облачный бэкап выключен (раздел 11).
- **`MIGRATION_2_3`** (явный SQL, без `fallbackToDestructiveMigration`):
  - переименовывает слоты в журнале и расписании;
  - создаёт `slot_state` — «записан» там, где есть записи; пустые слоты прошлых дней строк не получают, автопропуска задним числом нет;
  - скрывает исходные блоки;
  - добавляет `meal_log.autoSkipped` и таблицу `dish`.
- **Разбиение на блюда** выполняет приложение при запуске, идемпотентно: `INSERT OR IGNORE` по ключу `(legacyBlockId, componentIndex)`.
- **Расписание:** время слотов переносится из типа дня, выбранного на сегодня, недостающие слоты берутся из второго расписания. «С» = середина между З и О, округлённая до 30 минут (по умолчанию 11:30). Цели ккал, белка и воды не меняются.
- **Схемы Room** лежат в `app/schemas/<flavor>/…/N.json`.
- **Проверки CI:**
  - инструментальный `MigrationTest` (`MigrationTestHelper`) на эмуляторе: база v2 с записями, остатками, своими блоками и продуктами после миграции сохраняет все количества;
  - смоук-тест ставит версию 1.1 и обновляется поверх.
- **Резервная копия:** схема 3; копии схем 1 и 2 импортируются и приводятся к схеме 3.

## Разделы 12–18 (версия 1.1.0)

- **Конструктор приёма (12)** — «Сегодня → Собрать из продуктов», «Записать приём → Изменить состав / Собрать из продуктов». Строки: продукт библиотеки, свой продукт, заготовка; живой итог ккал/белка и предупреждения дня. Списание по FIFO, без ухода в минус; нехватка помечается «без списания» / «частично». В журнал пишутся состав (`MealLog.items`) и исходный блок (`basedOnBlockCode`). Итог изменённого блока = блок × множитель + Σ(новый состав) − Σ(исходный). Недельные счётчики берутся из тегов продуктов (рыба, жирная рыба, красное мясо, яйца, морепродукты). «Сохранить как свой блок» создаёт блок `M1`, `M2`…; в планировщик он попадает, только если укладывается в диапазон ккал своего типа (±10%) и правило белка. Свои блоки входят в резервную копию; удаление делает блок неактивным, журнал не трогается.
- **Библиотека продуктов (13–15)** — «Ещё → Продукты». Единая форма «Добавить в библиотеку» на всех экранах выбора (на 100 г / на порцию / на штуку, псевдонимы, теги, сырой/готовый, съедобная доля, «с этикетки»), пакетный ввод, поиск похожих перед добавлением. Источник: справочник / этикетка / свой (значения справочника показаны с «≈»). Использованный продукт не удаляется, а скрывается. Засев расширенного каталога идемпотентный: новые справочные позиции добавляются, правки пользователя не затираются.
- **Поиск и сортировка (16)** — нормализация (регистр, ё→е, иврит без огласовок и конечных форм), поиск по нескольким словам и основам, ранжирование, режимы сортировки (сохраняются), фильтры: категория, избранное, в наличии, без солёного, скрытые.
- **Инвентаризация (17)** — «Кладовая → Инвентаризация» или из «Импорта». Строка: `название | количество | единица | ≈ | до ДД.ММ`. Режимы: добавить к остатку, инвентаризация (перечисленные = как указано), инвентаризация с обнулением (с подтверждением списка). Предпросмотр «было → станет», отмена последней инвентаризации. Промпты для списка и фото холодильника; в сборке `api` — «Распознать по фото».
- **Что приготовить (18)** — «Сегодня → Что приготовить», «Ещё», и действие «Варианты из холодильника» в вечернем прогнозе при нехватке белка. Уровень 1 — блоки (×0,5–1,5), уровень 2 — рецепты офлайн-книги `assets/cookbook.json` (48 рецептов) и шаблоны по ролям продуктов. Допуск: ккал ±10%, белок ≥ 90% цели. Жёсткие исключения: недельные лимиты красного мяса и яиц, готовое/переработанное (если не разрешено), скрытые, солёное в рецептах. Приоритет продуктам с близким сроком. Фильтры: способ (сувид, Ninja, без плиты), только свои, разрешить готовое. Вкладка «Использовать остатки» — блюда на 2 дня. Рецепт можно сохранить как свой (правки не затираются при обновлении книги). Расчёт — в фоне, с кэшем по состоянию кладовой.
- В подборе «Что приготовить» буквы рецептов книги прежние: С в `cookbook.json` — «обед с собой» (чип «С · Обед с собой»). «Будний вечер» — воскресенье–четверг (израильская рабочая неделя): вечером в будни рецепты с активной работой > 20 минут не предлагаются.

### Обновление с версии 1.0.0

База данных переходит на схему 2 миграцией `MIGRATION_1_2` без потери данных: новые поля получают значения по умолчанию, продукты пользователя помечаются «свой», затем справочник дополняется расширенным каталогом. CI проверяет это на эмуляторе: ставит 1.0.0, запускает, ставит новую версию поверх (`adb install -r`) и обходит экраны.

Debug-сборки подписываются постоянным ключом `app/debug.keystore`, поэтому следующие версии ставятся поверх. **Версия 1.0.0 была подписана временным ключом CI, поэтому 1.1.0 поверх неё не встанет:** в 1.0.0 сделайте резервную копию (Настройки → Резервная копия), удалите приложение, установите 1.1.0 и восстановите копию. Копии схемы 1 принимаются. Для публикации нужен отдельный приватный release-ключ.

## Форматы импорта

### Строка покупки (5.1)

```
название | количество | единица | цена
```

- Разделители `|`, `;` или табуляция; CSV-файлы с запятыми конвертируются автоматически.
- Единицы: г, кг, мл, л, шт. `кг → г ×1000`, `л → мл ×1000`. Без единицы — шт. Цена необязательна.
- Десятичная запятая допустима, слитная запись `1.5кг` разбирается; допустима запись без разделителей `Картофель 1.5кг`.
- Строки с `#` и пустые игнорируются (строки `#` показываются как «неразборчивые»).
- Сопоставление с каталогом: точное → псевдоним → нечёткое. Новое название, связанное с продуктом, сохраняется как псевдоним.
- Лимиты недоверенного ввода: 1 МБ, 2000 строк, название ≤ 120 символов, проверка диапазонов.

### Строка этикетки (5.2)

```
название | ккал на 100 г | белок на 100 г | размер порции г | ккал на порцию | белок на порцию
```

Обязательны название и значения на 100 г; если указана только порция — значения на 100 г пересчитываются. Результат сохраняется как «Свой продукт» (CustomFood).

### Промпты

Кнопки «Скопировать промпт для чека/этикетки» (Закупки → Импорт). Промпт для чека подставляет актуальный каталог (кроме приправ-«мелочей»).

## Режим Claude API (только сборка `api`)

Выключен по умолчанию. Ключ вводится в Настройках, хранится в EncryptedSharedPreferences (Android Keystore), не логируется и не попадает в резервную копию. Перед первым запросом — предупреждение о платности. Запрос отправляется только по кнопке «Распознать по фото»: изображение (уменьшено до 1568 px, JPEG) и промпт 5.3/5.4. Ответ проходит тот же парсер и экран проверки. Используется официальный Anthropic Java SDK. Модель по умолчанию — `claude-opus-5-5`, выбирается в Настройках. Без ключа или при ошибке сети — копирование промпта.

## Резервная копия

Настройки → Резервная копия. Экспорт/импорт через системный выбор файла (SAF).

```json
{
  "format": "ration-backup",
  "schemaVersion": 3,
  "encrypted": false,
  "payload": "<JSON BackupData>"
}
```

Зашифрованный вариант: `encrypted: true`, `kdf: "PBKDF2WithHmacSHA256"`, `iterations: 210000`, `salt`, `iv` (base64), `payload` — base64 шифротекста AES-256-GCM (AAD = `ration-backup`). Пароль нигде не хранится.

`BackupData`: `schemaVersion, exportedAtMillis, settings, products, stock, purchases, purchaseLines, blocks, blockIngredients, prepTemplates, preps, mealLogs, customFoods, substitutions, dayPlans, plannedSlots, quickLogs, weights, bp, recipes, slotStates, dishes`. Импорт: лимит 20 МБ, строгая схема (лишние поля отклоняются), проверка диапазонов и ссылочной целостности, замена базы одной транзакцией — при ошибке данные не меняются. API-ключ в схеме отсутствует.

## Что редактирует пользователь

- Настройки: цели ккал, белка и воды; время шести приёмов; напоминания о перекусах; пороги закупки (40/20); задержка напоминания об отметке; вечерний прогноз; проверка закупок; тихие часы; день и время взвешивания и заготовки; кофейный лимит; блокировка; режим Claude API. Остальные параметры раздела 6 (контрольные суммы, недельные лимиты, пороги предупреждений) лежат в `AppSettings` и переносятся резервной копией.
- Кладовая: остаток, партии со сроком, нормальный запас (ручной или по последней закупке), «не отслеживать».
- Блоки: ккал и белок, замены ингредиентов (постоянные и разовые).
- Продукты из импорта: создание, псевдонимы; свои продукты с этикеток.

## Какие данные хранятся и как их удалить

| Данные | Где |
|---|---|
| Продукты, партии, покупки, блоки, блюда, заготовки, журнал питания, статусы приёмов, расписание, вода/кофе/алкоголь, вес, давление | Room `databases/ration.db` |
| Копии базы перед миграцией (2 последние) | `files/backup/pre-migration-<версия>.db` |
| Настройки, состояние порогов, отправленные предупреждения | DataStore `datastore/settings.preferences_pb` |
| API-ключ (сборка api) | EncryptedSharedPreferences `secure_prefs` |
| Временные отчёты для врача | `cache/reports/` (удаляются при следующем экспорте и через час) |

Полное удаление: Настройки → «Удалить все данные» (база, настройки, ключ, кэш отчётов; справочники засеиваются заново) или удаление приложения (удаляет и копии перед миграцией). Облачный бэкап Google и перенос на новое устройство отключены.

## Отклонения и разрешённые противоречия ТЗ

- Пищевая ценность продуктов хранится на 100 г для всех единиц (для «шт» пересчёт через `gramsPerPiece`) — так записана таблица 9.1.

- Неделя счётчиков — с понедельника, сброс после воскресенья (6.5 и раздел 3 согласованы так).
- «Субботняя партия» (в 9.2 названа «воскресный шаблон») запускает курицу, картофель с бататом и яйца.
- Раннее переедание проверяется по обоим правилам: 70% до 15:00 (раздел 4) и 60% до 12:00 (6.5).
- «Поделиться» принимается главной Activity (единственный экспортируемый компонент), а не отдельной.

- Библиотеки подмешивают в манифест: `USE_BIOMETRIC` и `USE_FINGERPRINT` (biometric — нужны для требования 11.2.4), `RECEIVE_BOOT_COMPLETED` (есть в списке), `${applicationId}.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` (core-ktx, signature-разрешение внутри приложения). `INTERNET`, `ACCESS_NETWORK_STATE`, `WAKE_LOCK`, `FOREGROUND_SERVICE` от WorkManager удалены через `tools:node="remove"` (сетевые ограничения, foreground-работы и SystemAlarmScheduler не используются; на API 26+ WorkManager работает через JobScheduler).
